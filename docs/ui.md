# Workspace UI

Open **Magpie → Plugins → Skill Workspaces** (技能工作区).

1. Choose a project in the top selector, or use `+` to add one. The optional manifest path defaults to `<root>/skills.manifest.yaml`; leaving it blank when re-adding a registered project keeps its current path. Source registration and Magpie Library discovery are in the `…` menu.
2. Choose a source and category, then check the skills to deploy. Clicking the skill row toggles its selection; clicking the skill name itself opens the shared reader. Use the category checkbox to select or deselect that category, preserving selections elsewhere. Its mixed state indicates a partial selection. When the draft differs from the project baseline captured on open or after the last sync, **Cancel changes** appears in the header and replaces the redundant unsynced label; it restores that baseline without writing or deploying. The button is hidden when there is no actual change. The page inspects actual deployment paths separately from manifest intent: a green **Exists** tag identifies a matching source link or intact owned copy. Unchecking changes it to amber **Will remove**, and rechecking restores green. New/unmanaged matching links are initially selected, while omissions of owned outputs from a saved manifest remain pending removals. Checkbox changes stay in the draft until Sync; Sync persists the manifest and deploys it together. Detection never adopts external links or permits removing them; the tag tooltip identifies unmanaged paths, and the existing ownership checks still apply. The second tab, **Existing**, enumerates every valid skill entry directly inside each real per-agent skills folder, including links and real directories, even when the selected source does not contain them. Each row identifies its type and folder; links also show their target. Valid entries open in the same Library-style reader as source skills; edits are written to the real skill folder or to a link's target. Broken links remain available for deletion but do not open. The trash button opens a confirmation naming the absolute path, type and link target. Deleting a link removes only the link, while deleting a real directory removes that directory and its contents; both revalidate the entry fingerprint on the server. A skill still selected in the manifest is recreated by a later sync. Whole-directory parent links are reported but not traversed, so their contents cannot be deleted through this list. A link at the per-agent skills path shows **Fix**; its dialog names the link, the target and the consequences, and repairing removes only the link, creates a real folder and re-checks the project. Higher-level parent links remain manual. The shared reader starts at SKILL.md; the header picker also opens files inside that skill. Markdown is rendered, and other UTF-8 text is shown verbatim. The truncated path in the footer opens the actual skill folder in the native file manager. **Edit** edits the selected file; **Save** writes it and returns to preview, while **Cancel**, switching files and closing protect unsaved changes. Saving refuses outside edits and invalid SKILL.md identity.
3. The top agent chips set project defaults; toggling them preserves button nodes so the selected state fades in and out. Hover backgrounds remain visible for selected/unselected agents and category tabs. **More agents** expands the remaining agents inline. Selected rows offer the same agent icons for overrides. The reset icon returns a row to project defaults. Tooltips and accessible names identify every icon.
4. Use **Preview → Sync**. Preview is a read-only dry run for the current draft. Sync validates and plans first, writes `skills.manifest.yaml` atomically and then deploys it, so a separate save step is unnecessary. The Manifest and Changes tabs provide YAML editing and the deployment plan. Conflicts name the affected path and distinguish a changed link target, a replaced link, edited copy content and permission-only drift, showing the recorded and current values where available. A target that already matches the intended output is shown as **Adopt** and only refreshes ownership instead of blocking the sync.
5. The `…` menu offers refresh, sync-all, opening the project folder and unregistering while keeping deployed files.

The page uses Magpie's official page bridge, including its base control styles and live theme/language events after navigating to the local service. Library agent-chip rules and upstream SVG assets are bundled with attribution. Skill rows reserve their agent controls' space while unselected; those controls are hidden, inert and excluded from accessibility navigation. Selection retains row geometry and control nodes, including when the layout wraps. Deployment badges, the skill count and the More agents toggle reserve space for their alternate states. Project/source pickers reuse Magpie’s protocol-menu styling and keyboard behavior. Skill readers reuse its dialog, metadata and Markdown styles, with focus trapping and Escape/backdrop dismissal. Hover, menus and expansion respect reduced-motion preferences. Markdown is rendered without raw HTML or remote images; local reference links are displayed as text. Only the workspace layout is plugin-specific; the palette and font come from `--magpie-*` tokens. Standalone CLI previews use Magpie's standard light/dark defaults.

The service accepts only loopback Host headers. APIs require a random token injected into its own HTML. Magpie's opaque-origin API and static icon requests allow Origin `null`; HTML never carries CORS headers. Library registry metadata is read-only. Explicit file saves update the selected source (and therefore existing links) or the resolved target of a workspace link; deployed copies require a later sync. Nested symlinks, binary files and files over 1 MiB cannot be edited. The file picker omits hidden folders/files and oversized files. Meanwhile, this plugin owns its own project deployments.
