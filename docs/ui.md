# Workspace UI

Open **Magpie → Plugins → Skill Workspaces** (技能工作区).

1. Choose a project in the top selector, or use `+` to add one. Source registration and Magpie Library discovery are in the `…` menu.
2. Choose a source and category, then check the skills to deploy. Use the category checkbox to select or deselect that category, preserving selections elsewhere. Its mixed state indicates a partial selection. Click a skill name to open its Library-style file viewer. It starts at SKILL.md; the header picker also opens files inside that skill. Markdown is rendered, and other UTF-8 text is shown verbatim. The truncated path in the footer opens the skill folder in the native file manager. **Edit** edits the selected source file; **Save** writes it and returns to preview, while **Cancel**, switching files and closing protect unsaved changes. Saving refuses outside edits and invalid SKILL.md identity.
3. The top agent chips set project defaults; **More agents** expands the remaining agents inline. Selected rows offer the same agent icons for overrides. The reset icon returns a row to project defaults. Tooltips and accessible names identify every icon.
4. Use **Save → Preview → Sync**. The Manifest and Changes tabs provide YAML editing and the deployment plan.
5. The `…` menu offers refresh, sync-all, opening the project folder and unregistering while keeping deployed files.

The page uses Magpie's official page bridge, including its base control styles and live theme/language events after navigating to the local service. Library agent-chip rules and upstream SVG assets are bundled with attribution. Project/source pickers reuse Magpie’s protocol-menu styling and keyboard behavior. Skill readers reuse its dialog, metadata and Markdown styles, with focus trapping and Escape/backdrop dismissal. Hover, menus and expansion respect reduced-motion preferences. Markdown is rendered without raw HTML or remote images; local reference links are displayed as text. Only the workspace layout is plugin-specific; the palette and font come from `--magpie-*` tokens. Standalone CLI previews use Magpie's standard light/dark defaults.

The service accepts only loopback Host headers. APIs require a random token injected into its own HTML. Magpie's opaque-origin API and static icon requests allow Origin `null`; HTML never carries CORS headers. Library registry metadata is read-only. Explicit file saves update the selected source (and therefore existing links); deployed copies require a later sync. Nested symlinks, binary files and files over 1 MiB cannot be edited. The file picker omits hidden folders/files and oversized files. Meanwhile, this plugin owns its own project deployments.
